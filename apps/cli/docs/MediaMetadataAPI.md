# Media Metadata APIs

Media metadata is managed through Core-backed RPC endpoints.

## POST /api/get-metadata

Read media metadata for an imported folder.

Request body:
```typescript
interface GetMetadataRequestBody {
  path: string;
}
```

Response body:
```typescript
interface MetadataSuccessResponseBody {
  data: MediaMetadata;
}
```

Status codes:
- `200`: Metadata returned
- `404`: Metadata not found (Problem Details)

## POST /api/create-metadata

Create metadata for a folder that does not yet have a cache entry.

Request body:
```typescript
interface CreateMetadataRequestBody {
  data: MediaMetadata;
}
```

Response body:
```typescript
interface MetadataSuccessResponseBody {
  data: MediaMetadata;
}
```

Status codes:
- `200`: Metadata created
- `409`: Metadata already exists (Problem Details)

## POST /api/set-metadata

Patch metadata fields for an existing folder.

Request body:
```typescript
interface SetMetadataRequestBody {
  path: string;
  patch: {
    type?: 'music-folder' | 'tvshow-folder' | 'movie-folder';
    mediaFiles?: MediaFile[];
    tvShow?: TvShow;
    movie?: Movie;
  };
}
```

Response body:
```typescript
interface MetadataSuccessResponseBody {
  data: MediaMetadata;
}
```

Status codes:
- `200`: Metadata updated
- `404`: Metadata not found (Problem Details)

## POST /api/delete-metadata

Delete media metadata cache for a folder.

Request body:
```typescript
interface DeleteMetadataRequestBody {
  path: string;
}
```

Response body:
```typescript
interface MetadataSuccessResponseBody {
  data: true;
}
```

Status codes:
- `200`: Metadata deleted
- `404`: Metadata not found (Problem Details)

## Metadata Cache Location

Metadata cache files are stored under `{userDataDir}/metadata/`. The cache file name is generated by replacing invalid filename characters in the folder path with underscores and appending a `.json` extension.
